2. Interface points (please read)

2.1 What I call

from hr_navigator.retrieval import search      # module path I import, by name
search(query: str, k: int = 5, filters: dict | None = None) -> list[Passage]
  • Best passage first. I use the order as given and trim from the end when the prompt is too long.
  • It may return [] (I treat that as "nothing found"). If it raises, I record a search_failed tool error and carry on, so it never crashes the agent.
  • I call it one query at a time from one thread. I currently never pass filters; tell me if you want me to (for example org or jurisdiction from the employee profile).
  • ToolBox(search_fn) takes the function as a parameter, so tests and your module do not clash.

2.2 What I need in each Passage

FieldWhy it matters to the agent
chunk_idMust be unique and stable. Citations are checked against it, and I de-duplicate passages by it. If it changes between runs, my cached results and eval records stop matching.
doc_id, titleShown in the citation and the UI section name.
textExact source text. The model must quote it word for word and my code checks the quote against it, so please do not normalise it (no lower-casing, no whitespace changes, no added headings). Chunk size: the whole prompt has to fit in 8192 tokens, so about 500 tokens or fewer per chunk works with 5 results.
org, jurisdictionThe answer prompt compares them with the employee's organisation. Empty values are fine but reduce the quality of "wrong organisation" answers.
synthetic, version_date, url, scoresUsed for reporting and the UI. Fill what you have.

3. Findings from real runs that affect you

  • The endpoint allows 1 request at a time, 8192 tokens in total and 1024 out. One agent question makes 4 to 8 model calls and uses 4,000 to 11,000 tokens in total. Do not run your own endpoint calls (for example embedding experiments) while an eval is running, or one of us gets a 429.
  • With no passages the agent says "the documents do not say". So an empty or failing search is visible in results straight away: please check search() on the 12 dev questions in data/dev before telling me it is ready.
  • Qwen3-8B tool calling works (valid JSON arguments). It repeated near-identical searches, so the agent now stops searching after one that adds nothing new. Search quality on the first query therefore matters a lot.
